# Hylo 陪伴空间设计方案

日期：2026-11-21  
状态：产品与交互方案，待视觉稿验证

陪伴空间是主 Hylo 的另一个视角。它让用户感到 Hylo 在这里、记得彼此的约定，偶尔带回值得了解的东西；用户也能看见当前活动，调整约定和主动性。

空间以陪伴体验为主，以信息洞察和掌控为辅。Hylo 的目的仍然是帮助用户更好地学习、记录和分享。笔记、知识库、播客和读书平台都是探索的资源。

## 1. 产品边界

主 bot 在现有界面中的位置和聊天入口保持不变，只为主 bot 增加进入空间的入口。空间与聊天使用同一个角色身份、约定和消息，不建立第二套助手机制。

空间应在没有新内容时也成立。用户可以进来停留、看一眼 Hylo，或者开始聊天，不需要处理事项才能离开。

第一版不包含：

- `/dev/pulse` 中的概率、预算、调用日志和内部简报。
- 打卡、连续陪伴天数、工作量排行或要求清空的未读计数。
- 角色养成、换装、家具摆放等复杂装饰系统。
- 独立的消息收件箱和质量评审系统。
- 对具体探索主题或长期追踪能力的无依据承诺。

## 2. 入口与页面关系

在主 bot 聊天顶部增加常驻的「空间」按钮，使用图标与文字组合，不藏入更多菜单。入口具有足够辨识度，不通过红点、闪烁或数量提示吸引点击。

空间打开在应用的主内容区域，提供完整页面的面积，不使用小弹窗。顶部提供「返回对话」和空间设置。进入或退出空间时保留原对话与阅读位置，不打断正在进行的工作。

点击发现后可以查看对应内容，并带着这条内容进入现有聊天继续讨论。打开空间本身不启动巡查，也不额外调用模型。

## 3. 视觉方向

### 3.1 三个视觉层次

| 层次 | 内容 | 作用 |
| --- | --- | --- |
| 环境层 | 壁纸、明暗、柔和遮罩 | 建立属于用户的氛围 |
| 陪伴层 | Hylo 角色、姿态、视线与状态文字 | 成为页面的主要视觉焦点 |
| 内容层 | 约定、发现与对话入口 | 承载有用的信息与操作 |

整体气质安静、舒展、有留白。默认背景可以带一点纸张和阅读的气息，但不将页面固定画成书房。更换为自然摄影、城市或插画后，构图仍应成立。

延续现有头像的角色语言、配色与表情，适当放大并丰富动作。使用已有组件、颜色、间距和圆角尺度，保持与应用其他部分的关系。

### 3.2 页面构图

桌面端顶部为轻量导航，中上部为舒展的陪伴区域，下方为内容区域。角色处在视觉中心附近，状态文字靠近角色；「聊聊」入口始终容易找到。

以下是信息位置示意，不规定最终比例、形状或颜色：

```text
返回对话                                  空间设置

                  自定义背景

                   Hylo
                 当前状态
                  聊聊

        记着的事                 最近的发现
        下一件约定               内容摘录或引用
        查看全部                 继续聊 / 查看内容
```

内容区不采用等大卡片矩阵。「记着的事」像一张清楚的便笺；发现按内容呈现为摘录、引用或媒体内容。条目较多时进入展开视图，不无限挤占主画面。

窄屏优先保留背景、角色和对话入口，内容在其下纵向排列，提供稳定的阅读底色。不能靠缩小文字容纳桌面布局。

### 3.3 角色与动态

动作应缓慢、短暂、有间隔。指针靠近时可以改变视线，点击时可以有轻微回应。角色回应不触发模型调用，也不是主要玩法。

探索时通过姿态或周围的小范围元素体现专注，例如翻阅的线条；避免整页持续运动。动画变化不引起内容跳动，阅读和操作时不抢夺注意力。

支持减少动态效果，状态变化同时有文字表达，不仅依赖颜色或动画。

## 4. 空间状态

当前活动、最近内容和约定是相互独立的信息：探索过程中仍可能有旧发现和约定，不能压缩成一个互斥的状态枚举。

| 情境 | 视觉与文案 | 数据边界 |
| --- | --- | --- |
| 安静 | 轻微眨眼或稳定画面；允许不显示状态句 | 不暗示持续后台工作 |
| 探索中 | 专注动作；「正在探索」 | 来自真实巡查状态 |
| 正在准备消息 | 延续活动状态，避免角色提前恢复安静 | 需关联后续聊天运行状态 |
| 有发现 | 一份内容出现在角色附近，形成视觉重心 | 仅使用最终已发出的消息 |
| 约定临近 | 对应便笺轻微突出，时间清楚 | 不将到期等同于提醒已送达 |
| 主动探索已关闭 | 环境与角色保留，明确显示已关闭 | 不将 bot 离线或状态获取失败误报为关闭 |
| 状态暂不可用 | 保持安静画面，必要时说明暂时无法获取状态 | 不播放代表真实探索的动作 |

角色装饰性的眨眼与真实工作的动作需要可区分。一次探索没有发现时自然回到安静，不生成「检查完毕，没有更新」的用户消息。

第一版不显示「正在读某本书」或「持续关注某个主题」，除非系统取得了可靠的活动信息。状态获取可以使用轻量接口，不要求持久化完整工具轨迹。

## 5. 记着的事

这是 agenda 的产品表达，展示用户交代或接受的后续事项。未被接受的建议和 bot 的临时探索计划不进入这一区域。

每项以自然语言展示事项与时间。优先呈现下一件约定，其余收进「查看全部」。无时间的事项明确显示没有指定时间，不制造紧迫感。

需要支持：

- 查看事项与时间。
- 修改内容或时间。
- 取消约定。
- 查看已完成事项，完成后退出主要区域。

取消与完成具有不同含义，应在数据和界面上区分。巡查曾为某事项醒过，不代表它已经完成或已提醒成功。

第一版不要求为全部历史 agenda 自动推断请求来源。历史条目需核对或明确归类，不能仅因存在于表中，就包装成用户确认过的承诺。

## 6. 最近的发现

使用已经发到聊天里的主动消息作为内容来源。内部 `brief` 和巡查 `summary` 不直接成为空间内容。

初版以短摘录、已有链接和引用呈现。点击后可以查看完整消息或继续讨论；需要稳定关联到原聊天与消息位置。

有结构化数据时，可扩展为不同内容表达：

| 内容 | 视觉重点 |
| --- | --- |
| 书籍 | 封面、书名、短书摘 |
| 播客 | 节目封面、单集标题、关键观点 |
| 笔记 | 标题、引用片段、笔记链接 |
| 一个想法 | 简短文字与必要来源 |

这些形态不是首版全部实现的前提。未取得封面、标题或来源信息时不补造。相同发现不产生新的未读状态，也不因进入空间再次通知用户。

没有发现时收起对应区域，保留完整的陪伴画面，不用占位内容催促用户连接 app 或制造笔记。

## 7. 自定义壁纸

壁纸铺满空间，是最直接的个性化方式。支持内置背景、用户图片、取景位置调整、明暗调整和恢复默认。设置时直接预览完整页面。

图片应保留原有气氛，默认不重度模糊。通过局部渐变与内容底色维持可读性，不依赖用户恰好选中一张合适的图。

角色和内容的位置需要在高亮、深色、细节丰富的背景下都清楚。窄屏重新取景，不能简单沿用桌面裁切。

第一版建议将壁纸偏好按当前设备与 vault 保存，避免大图和设备取景设置直接进入笔记内容。是否跨设备同步，在实现前明确；图片上传与保存失败时保留旧背景，不影响空间其他功能。

## 8. 核心交互

| 操作 | 反馈 |
| --- | --- |
| 点击空间入口 | 进入空间，呈现当前真实状态 |
| 点击「聊聊」 | 返回主 bot 对话，保留聊天上下文 |
| 点击发现 | 展开原内容，可携带内容继续聊 |
| 点击约定 | 查看并修改时间、内容，或取消 |
| 打开空间设置 | 预览壁纸与动态效果设置 |
| 返回对话 | 恢复原对话位置 |

具体探索来源的展开仅在有可靠数据时提供。角色点击、查看状态和进入对话的触发区域要清楚，不将整个角色变成含义不明的大按钮。

暂停主动探索可以作为后续控制项，但必须有真实生效的后端支持，并明确是否影响已约定提醒。第一版不展示一个只改变动画的暂停开关。

## 9. 当前数据能力与实现缺口

以下依据 2026-11-21 的代码结构，区分已有能力与需要实现的产品适配。

| 模块 | 已有能力 | 需要补齐 |
| --- | --- | --- |
| 主 bot 身份 | 名字、头像与角色动画 | 空间布局及角色表现 |
| Pulse 状态 | `Running`、活跃时段、最近巡查与最终投递状态 | 面向空间的轻量状态接口和更新机制；衔接聊天处理阶段 |
| Agenda | 事项、时间、创建与关闭信息；查看、新增、关闭接口 | 修改接口、取消与完成区分、完成记录查询、历史事项归类 |
| 发现 | 最终主动回复、聊天消息标识与正文 | 查询与消息定位适配；后续可补媒体展示字段 |
| 壁纸 | 现有主题和外观偏好机制可参考 | 图片保存、取景、明暗与偏好存储 |
| 具体探索主题 | 暂无稳定的产品数据 | 首版不承诺展示 |

关键语义：

- `pulse_runs.brief` 是候选简报，不能等同于已交付内容。
- `delivery = sent` 表示消息已产出，不表示用户已阅读。
- `bot_agenda.fired_at` 表示巡查已因事项醒过，不表示提醒成功送达。
- 现有关闭状态不足以区分完成和取消，不能仅修改前端文案。

数据结构参考：`internal/mate/pulse.go`；agenda 接口参考：`internal/server/handler/agenda_api.go`；实时状态参考：`internal/pulse/pulse.go`。

此次不新增质量评分、独立评审 agent 或完整探索日志。消息质量继续通过 prompt 引导，并定期抽样分析。

## 10. 第一版范围

第一版包含清楚可见的空间入口、完整陪伴页面、安静与探索状态、自定义壁纸、约定展示及必要操作、最终主动消息摘录和返回聊天。

优先保证角色、背景和留白共同形成舒服的画面，再接入信息。实现时先打通最小的真实状态与数据映射，不用模拟过程填满视觉设计。

首版暂不包含具体探索主题、长期关注清单、全部媒体内容形态、复杂装饰以及独立暂停策略。

## 11. 视觉稿与验收

视觉稿至少覆盖以下场景：

1. 安静状态，没有新发现，也没有约定。
2. 正在探索，同时有一件真实约定。
3. 有一条发现，可以查看并继续聊。
4. 同一页面分别使用浅色、深色、细节丰富的自定义壁纸。
5. 编辑与取消约定、调整壁纸的展开状态。
6. 窄屏、减少动态效果以及状态暂不可用。

验收重点：

- 不改变现有 main bot 的位置和聊天习惯，入口可发现。
- 空页面依然完整，没有需要用户清空的信息负担。
- 角色是主要视觉焦点，约定和内容在需要时容易找到。
- 壁纸更换后文字仍清晰，构图仍成立。
- 探索动作与真实状态一致，打开页面不触发额外巡查。
- 发现能回到原消息，约定操作作用于真实数据。
- 所有核心操作可用键盘完成，减少动态效果不损失状态信息。

视觉上需要达成的体验是：用户没有事情要处理时，也愿意进来停留；有事情想了解时，又能很快找到。
